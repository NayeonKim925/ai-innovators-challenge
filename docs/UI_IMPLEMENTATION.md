# 조사 워크스페이스 UI 구현 기록

2026-09-17. 이번 단계는 분석 모델을 바꾸는 작업이 아니라, 기존 API의 조사 흐름을 실제로 조작 가능한 업무 UI로 연결하는 작업이다.

## 디자인 결정

- 네이비 사이드바 + 청록 실행 버튼 + 밝은 회색 캔버스. 상태에만 제한적으로 색을 쓴다.
- Pretendard Variable 로컬 제공, Lucide 아이콘, 생성형 이미지로 만든 열린 육각형/신호 연결 로고.
- 후속 브랜딩에서 **Cluephase(클루페이즈)** 적용. “신호를 근거로, 근거를 판단으로.” 이름은 제품 작업명이며 상표·도메인 사용 가능성 검토는 미완료다. [브랜드 가이드](BRAND.md), [브랜드 보드](brand-board.html).
- Lazyweb quick-references 스킬/MCP를 먼저 사용했으나 도구 목록 이후 HTTP429로 검색 불가. Linear, Metabase, Grafana 공식 자료로 대체했으며 Lazyweb 검색 결과로 표기하지 않는다.
- [DESIGN.md](../DESIGN.md)가 디자인 원본이며 [레퍼런스 기록](../.lazyweb/quick-references/investigation-2026-09-17/report.md)에 채택·제외 이유를 남겼다.

## 사용자 흐름과 실제 데이터

1. 준비된 사건 목록을 API에서 읽는다. 임의 사건이나 가짜 KPI를 만들지 않는다.
2. 관측 타임라인은 실제 기록을 48개 시간 구간으로 집계한다. 센서값을 임의의 연속 곡선으로 합치지 않는다.
3. 사용자가 진단 시점을 정하고 조사한다. 기본값은 관측 끝이며 알람 해제 후라면 후보가 없을 수 있다.
4. `최근 알람 발생 시점으로 이동`은 공개 관측 중 마지막 `Alarm=True` 시점이다. 평가 라벨이나 정답 진단 시점을 사용하지 않는다.
5. 후보를 선택하면 연결 근거를 보여주고, 분석 한계·도구 실행 기록을 열어볼 수 있다.
6. 전문가 검토 승인/재검토 의견을 저장한다. 이 동작을 물리적 원인 확정으로 표시하지 않는다.
7. 현재 조사에 질문하거나 근거와 검토 이력을 Markdown으로 내려받는다.

## 실행 구조

브라우저 → 같은 출처 Node 게이트웨이 → 기존 FastAPI → 기존 분석 도구/선택적 Bedrock.

백엔드 토큰은 서버 환경에만 있으며 브라우저에 노출하지 않는다. 게이트웨이는 알려진 API 경로와 메서드만 허용하고 POST Origin, 본문 크기, timeout, 경로 이탈을 검사한다. 공유 검증 환경이며 개인별 인증을 대신하는 구조는 아니다.

## 검증

- TypeScript strict typecheck + Vite production build 통과
- Node 테스트 10개: 프록시/키 비노출, API allowlist, ingress Origin, 경로 검증, 크기 제한, 캐시, 한국어 표시, 브랜드 상수와 정적 메타데이터 일치
- 기존 Python 백엔드 테스트 47개 통과, 외부 라이브러리 deprecation 경고 10개
- 실제 로컬 API Playwright 3개 통과: 조사→근거→검토→질문→다운로드→기록 복원, 390px 모바일/빈 데이터/키보드 접근, API 실패 후 재시도
- 기본 흐름은 LLM 없이 검증했다. Bedrock의 생성 품질/지연 개선을 이번 UI 검증으로 주장하지 않는다.
- [데스크톱](ui/desktop-workspace.png), [분석 결과](ui/desktop-results.png), [모바일](ui/mobile-workspace.png)
- 브랜드 적용 후에도 같은 테스트가 통과했다. 보고서 파일명·표지·안전 문구, 브라우저 제목·접근 가능한 브랜드 링크, 안내 페이지의 로고 decode를 추가 검증했다. [브랜드 안내](ui/brand-guide.png), [브랜드 보드 캡처](ui/brand-board.png).
- 추가 정적 검사에서 기존 백엔드 Ruff 지적 47건(E501 줄 길이 44건, I001 import 순서 3건)을 확인했다. 이번 변경은 백엔드 diff가 없으며 해당 스타일 정리는 범위 밖으로 남겼다. 프론트 typecheck/build, 게이트웨이/배포 스모크 스크립트 구문 검사와 `git diff --check`는 통과했다.

## AWS 반영

- 기존 ECS Express 서비스의 네트워크·역할·환경값을 보존하고 이미지와 health 경로만 교체했다. 기존 Streamlit 이미지는 복구 가능하도록 보존했다.
- [공개 프론트](https://mf-402d7cdcc2334f2c849cfe7485511d5c.ecs.us-east-1.on.aws)에서 React 화면 HTTP200, 실제 조사 POST200, 후보1개/근거1개, 브라우저 오류0개를 확인했다.
- 이 확인은 최근 활성 알람 시점으로 이동한 causRCA 사건1건의 결정론적 흐름이다. LLM 호출·전문가 승인 없이 검증했다.
- [실제 배포 화면](ui/deployed-workspace.png). 새 이미지 digest: `sha256:e45385f6c1c1c10e7b08c2560a6f77171cdd1afa973ef7281e865ce75314fc27`.
- 기본 카나리 배포/롤백 보호는 유지했다. 공개 UI 검증 이후 안정화 대기까지 종료되어 AWS 서비스 배포 상태 `SUCCESSFUL`을 최종 확인했다.

## 남은 서비스 작업

1. 사용자 인증·조직별 권한·요청량/비용 제한. 공개 공유 링크는 검증 환경으로만 사용한다.
2. Bedrock 해설 생성/실패/가드레일 상태의 실서비스 검증. 현재 UI는 선택적 API 기능을 연결한 수준이다.
3. 도메인 전문가의 용어 사전과 데이터에 맞춘 신호 설명. 현재 신호 ID를 임의로 해석하지 않는다.
4. 관측 테이블 페이지네이션과 서버 측 조사 목록. 지금 목록은 이 브라우저에 기록된 조사 ID 기준이다.
5. 전문가 사용성·접근성 테스트. 자체 시각 검수는 접근성 인증을 의미하지 않는다.
